# B410 Consolidation Module

## 1. Outcome
A new module in AuditSoft for Team Leaders to drag-and-drop multiple B410 working papers (`.xls` and `.xlsx`) from team members. The module will automatically extract text, rich-text formatting, and embedded images from the issue summary table, aggregate them into a single master B410 file, and copy any attached extra sheets to the master file.

**Enhancements (Data Tracing):** 
The master file will include automatically generated technical columns (Source, Creator, File Name, Source Sheet) appended to each issue row, ensuring the Team Leader can trace any issue back to its exact origin.

## 2. Constraints
- **Excel COM as Primary Engine:** Because pure JS libraries (like ExcelJS) cannot perfectly recreate shapes, floating images, exact row heights, and merged cells during an append operation, the module will rely entirely on Microsoft Excel COM Automation (`Range.Copy`, `Worksheet.Copy`) via a background script to perform the merge.
- **Realistic Preservation Limits:** Preserves cell content, rich text, formatting, images, and attached sheets based on tested B410 templates. Special objects like ActiveX, macros, external links, charts, or protected workbooks will generate warnings if unsupported.
- **Robust Execution Rules:** 
  - Sequential processing only (no parallel COM tasks).
  - Strict COM cleanup (`try/finally`, `Excel.Quit()`, object release) to avoid orphaned `excel.exe` processes.
  - Prohibition of brute-force `taskkill` to protect the user's unrelated active Excel sessions.
  - Sheet naming rules strictly enforced (max 31 characters, sanitization of invalid characters, suffixing `_02`, `_03` for collisions).
- **Data Boundary Definition:** The script will determine the `lastDataRow` by scanning a mandatory column (e.g., "Thực trạng Doanh Nghiệp" or "Hướng xử lý"), stopping at footers, sub-totals, or signatures.

## 3. Non-goals
- No validation of accounting/auditing accuracy within the text.
- No deduplication of semantically identical issues submitted by different members.
- No modifications to other working papers besides B410.

## 4. Acceptance Criteria
- [ ] **Data Integrity:** Master file opens cleanly without the "We found a problem with some content" warning.
- [ ] **Visual Integrity:** Images are verified to align with their correct rows post-append; sheet copies retain print areas, merged cells, and page setup.
- [ ] **Robustness:** A corrupted, password-protected, or invalid B410 file skips gracefully without crashing the entire batch process.
- [ ] **Isolation:** Works safely even if the user has other Excel files open simultaneously. Source files are NEVER modified.
- [ ] **UX/Reporting:** Displays a final summary report detailing successful files, failed files, total rows merged, and total images processed. If MS Excel is not installed, the UI detects this proactively and guides the user.

## 5. Technical Approaches Considered

**Approach A: Excel COM Engine (Recommended)**
- *How:* Electron invokes a background script (PowerShell/VBScript or packaged executable) that handles the *entire* read, copy (`Range.Copy`, `Worksheet.Copy`), and save operation via Excel COM. `exceljs` is demoted to simple pre-flight checks (validation, reading metadata).
- *Trade-offs:* Requires careful COM memory management and sequential execution, but solves the immense complexity of reconstructing Excel objects programmatically.

**Approach B: ExcelJS for Merging**
- *How:* Convert `.xls` to `.xlsx`, then parse and rebuild with ExcelJS.
- *Trade-offs:* High risk of breaking visual fidelity (images, merged cells, row heights, print layouts). REJECTED based on architectural review.

## 6. Next Steps (Action Plan)
Do not proceed directly to implementation (`ak-cook`). Transition to the **Planning Phase (`ak-plan`)** accompanied by a **Technical Spike**.
The Spike must prove the Excel COM engine against 5 real-world edge cases:
1. An `.xls` with images.
2. An `.xlsx` with heavy rich text.
3. A file with multiple attached sheets.
4. A file with complex merged cells/images spanning multiple rows.
5. A corrupted/locked file or one opened by another process.
